# 《查手机》特效与打击感

## 开工前必须问清

1. **这个效果要表达什么？** 打击感 / 战况读数 / 信息传达，三者做法完全不同。
2. **同屏最多几个？** 决定用不用对象池、池满怎么处理。
3. **改完怎么验？** 特效必须拍胶片看，不能靠想（见 `chashouji-verify`）。

## 一、配色：这张底图不让你"更亮"

底图是明亮客厅（浅绿墙、米色地板）。**加色混合的可见度取决于底图离饱和还有多远，
而这里几乎为零——亮度这条通道整个失效。** `lighter` 白闪 **0.22 就到顶**，
再高直接过曝糊掉人物。

同一个病在三处各暴露过一次：全屏白闪叠成一片白 / 对抗线光柱走 lighter 只剩一团雾
（这就是用户说"表现力特别差"的根因）/ 奶白火花 + 浅米碎片在胶片上根本看不见。

**规则**：

| 要表达 | 做法 |
|---|---|
| 发光 | 高饱和**暖橙** `EMBER = [255,156,38]`，靠**色相**跳出来 |
| 实体 | 深色 + 描边 `INK = [58,44,38]`（取角色线稿那个暖黑），靠**轮廓**跳出来 |
| 自发光 | **色晕**：普通混合的半透明高饱和色，比本体大半圈、边缘柔化 |

粒子有 `edge` 描边字段——跟赛璐璐角色有线稿是同一个道理，这类画风里"看得见"
本来就靠轮廓。

**"把它改成深色"往往是绕开这条规律，不是在用它。** 做礼物物品时撞过一次：白相纸
的照片在这张底图上看不见，我把整张压成复古棕——看得见了，**但不再像照片**。规律
说的是"靠轮廓"，不是"别用浅色"。回到浅相纸 + 描边加粗到 3.6 的深棕框，两个目标
才同时成立。判据：**修完之后那个东西还是不是原来那个东西？**

同一条的另一种用法：一个配方里可以让**不同粒子分担不同职责**。奶茶泼溅的浆是浅
焦糖（负责"湿了一片"、糊住不动），可见度整个交给**深褐色的珍珠**扛。不必逼着每
一种粒子都自己解决对比度。

**色晕别给大。** `r*2.5 + alpha 0.88` 会把浅粉被子整块洗成发光板，格纹和翻角全没。
它是物体边缘的一圈光，不是一团雾。

**同一条弹道上"发光层"和"实体层"必须用不同色系。** 色晕、亮芯（光，靠色相）和
轮廓残影（形状，靠轮廓）全用同一个高饱和色会融成一条实色带，形状就没了——
残影改用 `TAIL` 暗调后才读得出。

## 二、弹道三层（`ammo.js`）

```
① 色晕      AURA 色表 → aura(rgb) 预渲染贴图，三团沿轨迹回溯
            强度 gk = 0.34 + p.near * 0.40  ——「飞到哪儿了」一路烧起来
② 暗拖尾 + 亮芯   梯形暗带 alpha 0.30 + 楔形亮带 alpha 0.48
③ 轮廓残影   4 个，只画 SILH 外轮廓剪影，TAIL 暗调，alpha 0.40 - k*0.068
④ 本体      ITEM 画法
```

**拖尾长度按距离算，不按帧数：**

```js
const TRAIL = 16, TMASK = 15;
const reachOf = (p) => Math.max(p.r * 2.6, Math.abs(p.vx) * 0.09);
```

固定回溯 8 帧时，被子 850px/s 只退了 113px，而被子本身就有 156px 宽——
整条拖尾埋在本体底下，画了等于没画；同样 8 帧，发卡（1400px/s、半宽 22）
却能拖出四个身长。**眼睛读的是"拖了多长"，那是距离不是时间。**
大件按身长拖，快件按速度拖，两条各自都会在另一头失效，所以是 `max`。

**残影不画完整物品。** 缝线、按键、格纹在高速移动里糊成噪点，而且四个残影 =
四遍完整物品，是 `ammo.js` 最贵的一笔开销。残影只需要形状 → 单独一张 `SILH` 表。

## 三、顿帧必须有不应期（`fx.js`）

顿帧的设计前提是**一次孤立的重击**——冻住之所以有力，是因为它打断了流动。
每秒九次命中时没有"这一击"可言，每次都冻就等于不冻，只剩画面不动这个副作用。

实测：连点时 **65% 的帧被顿帧冻住**，而帧均值 2.98ms、掉帧率 0.2%。
把礼物间隔放宽三倍冻结率还是 64.8%——**撑起它的不是礼物密度，是"每一击都冻"
这条规则本身**。

```js
function hitStop(sec) {
  if (sec <= 0) return;
  if (cool > 0 && sec <= lvl) return;   // 不应期内只接受更重的一击
  stop = Math.max(stop, sec);
  lvl = sec;
  cool = sec * 3;                        // 冻 sec，再流动 2*sec，占空比封顶 1/3
}
```

主循环里的档位：`Particles.hitStop(power >= 3 ? 0.11 : power >= 2 ? 0.07 : 0)`
——**点赞级（power 1）不顿帧**。一串八颗各冻 35ms 会把"哒哒哒"拆成八次停顿，
而它的表现力全在快。

**连带的坑**：顿帧冻住时走逻辑时钟的弹幕也停住、飞不到线上，在池里堆积。
`fire()` 池满时原本静默丢弃**新**发射的——观众刷了礼物屏幕上什么也不飞。
改成回收最老的那一发（`act` 按发射顺序排，队头飞得最久、离对抗线最近）：

```js
if (act.length >= MAX) pool.push(act.shift());
```

效果：110ms/件 冻结率 65.0% → 30.2%；300ms/件 17.1%。
弹幕池 均 53.8 峰 78 → 均 32.5 峰 48。

## 四、粒子（`fx.js`）

- **淡入用绝对时间，不能按寿命比例**——按比例会让长寿命粒子迟到三分之一秒。
- **颜色串和贴图在 spawn 时预生成**（`p.fill` / `p.line` / `p.tex`）。写在 draw 里
  就是每帧、每颗粒子重拼一次字符串、让浏览器重新解析一次颜色——场上常有三五百颗，
  一秒钟要算上万次。
- 池 `MAX = 1200`，实测峰值 862，够用。
- 配方在 `main.js` 的 `RECIPE`：`thud` / `feather` / `star` / `debris` /
  `petal` / `splash`（档 3）/ `bloom` / `memory`（档 4 绽放式）。
- kind 共八种。发光三种 `dot` / `spark` / `ring`（无描边，它们本来就该是光），
  实体五种 `soft` / `chip` / `star` / `heart` / `card`（吃 `edge` 描边）。

**`chip` 的语义是"空中翻滚的薄片"，需要稳定矩形时必须另开 kind。** 它带描边时
圆角被拉到 `min(w, hh*2) * 0.5`（短边收成半圆），外加按 `cos(rot * 1.7)` 压扁，
而 `rot` **初值就是随机的**——粒子一出生就被压扁了，`vrot` 调到多小都没用。
做照片雨时在这儿卡了两轮才想明白：调参数是修不好的，那是补丁。`card` 因此诞生
（不压扁、不圆角、带一块内芯）。`heart` 同批加的：负重力往上飘。

**尺寸参数乘上分量系数 `s` 之后会失控。** 档 4 的 `s = 2.8`，`r: (15 + rand*16) * s`
得到半径 42~87，一颗爱心 190px 宽、占屏宽五分之一，四十二颗把两张脸全糊死——
而脸是这个玩法仅有的两个可读信息之一。**密度靠数量，不靠单颗更大**（这条在
`feather` 的注释里早写过一次，还是又踩了）。写 `r` 时先把最高档的 `s` 乘进去算一遍。

## 五、聊天气泡（`bubble.js`）

这个玩法争的是一部手机，而手机里有什么此前画面上一个字都没交代——观众看得到
两个人在拔河，看不到他们**为什么**拔河。

**位置按底版量出来的**：用 PIL 把 `bg.jpg` + 一张角色帧合成带坐标网格的图，
一眼看出手机在 y≈650、脸在 520~610，而 **y=150~470 那片墙完全空着**。
气泡从手机正上方升起、穿过两人中间那条缝，停在墙上——不挡脸也不挡手。

**上下两个硬边界**：下边界是出生点（手机上方 44px，那里是沙发）；
上边界是血条 y=74~105。约束 `RISE + 3*STACK ≤ 341`，现取 `RISE=140, STACK=64`。

**只有最新一条带尾巴**（`b.st === 0`）。都带尾巴读起来是每条从下面那条冒出来的——
而它们其实都来自同一部手机。

**四类消息**：`text` 日常给密度 / `hot` 暧昧给动机 / `sys` 撤回·正在输入 /
`voice` 语音条。**后两类什么都没说，反而最让人往下想。**
全程不出现露骨的词——观众自己脑补的永远比写出来的狠，这同时是平台红线要求。

按权重随机，日常最多、关键的几句要稀。越僵持发得越急
（`gap = (1.5 + rand*1.3) * (1.35 - struggle*0.5)`）——五五开时两边谁也拽不动，
画面信息量最少，正好让手机替他们说话。

## 六、层次顺序

```
底版 → 角色帧 → 对抗线/指针 → 刻度尺 → 气泡 → 弹幕 → 粒子 → HUD → 全屏闪
```

**对抗线必须画两遍**：一遍在角色之下当背景光柱，一遍以 ~0.4 强度盖在角色之上。
两个人正好在中间抢手机，只画在下面的话它全程被两具身体挡死，
而它是这个玩法唯一的战况读数。

## 七、"卡顿"先别当性能问题

帧率满格、画面不动，观众读到的同样是卡。排查这类问题**必须同时量三个数**：
帧耗时分布、掉帧率、**冻结帧占比**。只看前两个会得出"没问题"的错误结论。
量法见 `chashouji-verify`。
